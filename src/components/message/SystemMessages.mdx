# System messages

System-origin content is generated by the platform rather than written by a human.
Carimat is its configurable assistant presentation; it is not another Matrix
account, transport or encryption-key owner. Several visual bubbles can represent
one stored event. Technical notices keep their own information, shield, calendar
or call symbols and do not acquire assistant authorship just because they are
listed here.

A **human message** keeps its human sender, audience, thread and delivery state.
An **event notice** records a fact (for example acceptance, access or reassignment)
whose original identity, time, wording and policy metadata remain authoritative.
The assistant sender line and the event/topic heading are separate: the heading
and topic icon sit in the first bubble, below the two-line sender/qualifier header.

This inventory opens maintained production components. Use viewport and locale
controls for the same responsive presentation on phone, tablet and desktop.

## Assistant presentation consumers

- [Pseudonym and privacy onboarding](?path=/docs/components-chat-carimatmessage--docs): actual session gates, with original reveal and confirmation behavior.
- [First response and FAQ](?path=/docs/components-chat-erstantwort--docs): one persisted first-response event; guidance, credential protection and notification setup share its presentation.
- [Consent and saved outcomes](?path=/docs/organisms-casehandover-clientcards--docs) and [handover continuation](?path=/docs/organisms-casehandover-conversationjourney--docs): request-scoped controls, not a replacement for a future preference.
- [Supervision](?path=/story/components-chat-messageitem--supervision-notice): assistant-presented derived notice whose supervision fact/title remains separate from the configurable assistant name.
- [Persisted handover](?path=/story/components-chat-messageitem--case-handover-granted): acceptance and access facts retain their immutable event metadata; optional notification setup is a local continuation.
- Compatibility waiting guidance remains conditionally rendered in the real session. Its old bell/hard-coded sample time is replaced by the same assistant presentation; existing visibility, sequencing and action callbacks are retained. Typing indicators are status UI, not additional messages.

The [archived breathing tutorial](?path=/docs/components-chat-breathingtutorialcard--docs)
is **story-only**: current waiting sessions mount `BreathingCompanionHost` instead.
The historical tutorial uses the same presentation for visual review, but its story
is not evidence that this retired flow runs in a production session.

## Existing links and device coverage

Category names have changed, but explicit story IDs preserve existing URLs.
The consent stories tagged **device-regression** remain for existing links and
browser checks (including narrow action alignment); they are regression scenarios,
not separate mobile components. Select a viewport on the main state stories for
ordinary design review. Pending, saved, denied, expired and informational behavior
is exercised by the handover journey as well as the consent scenarios.

## Approved icon family

The consent dialog uses the supplied **400** artwork for Einsicht, When useful,
Your consent and Protected access. The additional filled surveillance-consent
asset is catalogued for future selected-state use. Find both in
[Icons & Avatars](?path=/docs/design-system-icons-avatars--docs).

Storybook is component evidence. Persistence, event timing and real chat placement
must additionally be checked in the running application.
